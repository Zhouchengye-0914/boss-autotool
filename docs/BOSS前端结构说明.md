# BOSS 直聘前端结构说明

检查时间：2026-07-19  
浏览器：Chrome 150 + DrissionPage 4.1.1.4  
会话：项目专用持久化用户目录，已登录  
检查方式：只读导航和 DOM 查询，没有点击沟通、投递或发送

## 1. 页面入口

| 页面 | 当前入口 |
|---|---|
| 杭州职位搜索 | `https://www.zhipin.com/web/geek/job?city=101210100&query={关键词}` |
| 搜索后的实际地址 | `/web/geek/jobs?city=101210100&query={关键词}` |
| 职位详情 | `/job_detail/{职位ID}.html` |
| 在线简历 | `https://www.zhipin.com/web/geek/resume` |
| AI 简历 | `https://cv.zhipin.com/smart-resume?from=3` |

不要直接以 `/web/geek/jobs` 作为首次搜索入口；实测部分关键词会得到空列表。应先访问 `/web/geek/job`，由站点自行跳转。

## 2. 搜索结果页

杭州“数据分析”页面实测：

- `.job-list-container`：1 个列表容器。
- `.job-card-box`：首屏 15 个岗位卡片。
- `a[href*="job_detail"]`：17 个链接，其中包含一个无职位 ID 的通用入口，采集时必须过滤。
- 当前页面没有 `.search-job-result`。

职位采集规则：

1. 读取 `a[href*="job_detail"]`。
2. 排除以 `/job_detail/` 结尾的空链接。
3. 排除文本“职位搜索”。
4. 按完整 URL 去重。

## 3. 职位详情页

实测稳定结构：

| 内容 | 优先选择器 | 说明 |
|---|---|---|
| 职位名称 | `.job-title` | 当前详情页唯一且可见 |
| 公司名称 | `.company-info a:not(:empty)` | 第一个公司链接可能是无文本 Logo，必须排除空文本 |
| 主沟通按钮 | `.info-primary .btn-startchat` | 位于主详情区，存在真实点击矩形 |
| 沟通按钮回退 | `.job-op .btn-startchat` | 主详情操作区回退 |

页面同时存在两个 `.btn-startchat`：

- 主详情区：父级链包含 `.btn-container`、`.job-op`、`.info-primary`，当前矩形约 150×45，可点击。
- 固定详情栏副本：父级链包含 `.btns`、`.detail-op`，当前虽然状态显示可见，但没有可用矩形。

因此不能对所有 `.btn-startchat` 直接取第一个或要求节点总数为 1。自动化必须优先使用主详情区作用域，并过滤没有有效矩形的元素。

当前“立即沟通”是 `<a href="javascript:;" class="btn btn-startchat">`，不是 `button`。

## 4. 简历页面

当前账号已识别到：

- 一份“我的在线简历”。
- `预览`：`.link-preview-resume`。
- `导入已有简历`：`.link-import-resume`。
- `导出为附件简历`：`.link-create-resume`。
- 页面提供“附件上传”入口。
- 本次只读检查没有识别到独立附件简历文件名。

后续任务的默认 `resume_name` 使用“我的在线简历”。如果沟通或投递弹窗未出现简历选择步骤，视为平台使用默认在线简历；如果弹窗出现，优先匹配“我的在线简历”或“在线简历”。

简历正文、姓名、电话和邮箱属于敏感信息，不写入本说明、日志、截图文件名或任务 JSON。

## 5. 登录和安全状态

- 顶部导航存在“消息”“简历”等入口，可以用于辅助判断登录状态。
- 未登录时可能出现扫码登录、登录/注册或安全验证区域。
- 登录页、验证码和安全验证只暂停调度，由用户手动处理。
- 页面 DOM 中可能存在隐藏的登录组件，不能只根据节点是否存在判断；还要检查显示状态和当前 URL。
- 实测职位详情 DOM 会保留“扫码登录”“登录/注册”“验证码”等隐藏模板；这些节点没有可用矩形。登录与安全验证判断必须要求当前 URL 为登录页，或提示元素拥有正尺寸矩形。

## 6. 自动化安全规则

- 沟通、投递、简历和发送按钮必须拥有有效矩形并可交互。
- 关键元素有多个有效候选时停止操作，不随机点击。
- 点击发送前必须再次核对职位、操作类型、招呼语和简历。
- 发送后必须看到成功提示、对话状态变化或“继续沟通”等明确标志。
- 结果不明确时截图并失败，重试前先检查是否已沟通，避免重复发送。
- 页面结构变化时只更新 `selectors.py`，不要在调度器中散落临时选择器。
- 招呼语输入框必须处于聊天或弹窗作用域；禁止使用全局 `input[type=text]`，否则可能把招呼语写进顶部职位搜索框。

## 7. 实测聊天页

- 点击沟通后可能先显示弹窗，也可能导航到 `/web/geek/chat`。
- 合法聊天弹窗不能被异常弹窗处理器自动关闭。
- 输入区：`div.chat-input[contenteditable=true]`。
- 页面同时存在内部 `textarea.input`，但优先使用 `.chat-input`。
- 发送按钮：`button.btn-send`，没有内容时带 `.disabled`，输入内容后才允许点击。
- 发送成功应通过消息文本出现或输入区清空确认。
